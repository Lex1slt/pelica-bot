# Pelica Console —— 开发启动提示词（Kickoff）

> **用法**：将下方代码块全文复制，发给具备本仓库访问权与命令执行能力的 AI agent（Claude Code / Codex CLI 级别）。
> 本提示词只做"路由 + 行为协议"，完整任务规范在它指向的两份文档里；三者配合使用，勿单独拆开。

```text
你是资深全栈工程师兼桌面端发布负责人。当前仓库是 pelica-wechat-bot（微信群机器人，Python 后端）。
你的任务：为它开发图形管理控制台，交付可直接验收发布的 v1.1.0 安装包——一步完成全部开发、测试、打包与验收，不需要我在过程中介入。

执行协议（立即开始，不要向我确认）：
1. 按序通读以下内容，它们是你的全部任务规范：
   ① docs/console-build-prompt.md —— 任务书（最高优先级，与你的自行判断冲突时以它为准）
   ② docs/console-design.md —— 设计规范（架构/设计系统/模块交互/schema）
   ③ 任务书 §3 列出的源码文件 —— 理解现有核心，禁止破坏其行为
2. 通读完毕后按任务书 §9 的顺序开工，自主连续执行到底（含工具链安装、打包、验收剧本）。
3. 全程不提问、不等待确认：未覆盖的决策按任务书 §12 歧义协议自行处理并记入 DECISIONS.md；
   验收失败的按 §15 修复重试（最多 3 轮），仍失败则如实报告 NO-GO，禁止任何交付形态降级。
4. 完成定义 = 任务书 §14 验收清单 A–E 五组全部 PASS；最后严格按 §16 格式输出 GO/NO-GO 报告。
5. 不可逾越的红线：不改写 .env、不修改 pelica/ 现有默认行为、不自动 git commit/push/发 Release、
   任何输出（日志/测试/报告）中不得出现明文 API Key。

现在从阅读 docs/console-build-prompt.md 开始。
```
