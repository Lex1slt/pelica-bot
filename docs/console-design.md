# Pelica Console —— 桌面端管理控制台设计方案

> 版本 v1 · 2026-09-22 · 配套文件：[console-build-prompt.md](console-build-prompt.md)（一步完成 P0 的开发提示词）
> 目标用户：不懂开发的普通用户与普通开发者。合格标准：非开发者 10 分钟内完成首次配置并测试成功。

---

## 0. 背景与现状资产映射

本方案不重写机器人核心，而是为现有 Python 后端加一层「本地网关 + 桌面壳」。所有设计都锚定仓库现有资产：

| 现有资产 | 位置 | 在控制台中的角色 |
|---|---|---|
| 角色包（人设） | `characters/{pelica,kaltsit,paimon}.toml` + 同名 `.persona.md` | 人设管理模块的一等数据源，格式不变 |
| 语料库 | `corpus/releases/<release>/`，`data/pelica.db`、`data/paimon.db` | 语料库卡片 + 检索测试台 |
| 全局配置 | `.env`（见 `.env.example`） | 降级为导入/导出格式，主存储迁至 `config.db` |
| 桥接 | `pelica/bridge/`：mock / wxhook / pyweixin / wechaty | 桥接选择器 + 诊断体检项 |
| 管道 | `pelica/pipeline/router.py`（GroupBot：三层触发/辱骂闸/限流/白名单） | 沙箱与对话回放的执行引擎 |
| mock 沙箱雏形 | `scripts/run_mock_chat.py` | 测试沙箱页直接 UI 化复用 |
| 测试基线 | `tests/`（pytest）+ `scripts/qa_regression.py`（17 条）等 | 验收门槛，任何改动不回归 |
| 发布流 | `scripts/package_release.py` → `dist/` | 控制台安装包并入现有发布资产 |

三条架构决策（已定）：

1. **配置主存储从 `.env` 迁到 SQLite（`data/config.db`），`.env` 降级为导入/导出格式。** 网关启动 Core 子进程时把 DB 有效配置注入为进程环境变量，现有 `pelica/config.py` 的 `load_settings` 零改动。首启时自动从已有 `.env` 导入，CLI 用户随时可导出。
2. **三进程架构：桌面壳 + Python 网关（sidecar）+ 现有 Core。** 壳只做 UI；网关是新增 FastAPI 进程，包装 `pelica` 包；Core 即现有 `main.py`。
3. **沙箱是 mock 桥的 UI 化，不是新功能。** 复用 mock 桥 + GroupBot 跑真实管道，"改配置 → 沙箱验证 → 再上真群"闭环成立。

## 1. 总体架构与技术选型

```
┌─ Tauri 壳 (React UI) ─────────┐
│  WebView ↕ localhost:随机端口+token │   ← 防本机其他进程嗅探
└──────────────┬───────────────┘
┌──────────────▼───────────────┐
│ 网关 FastAPI (sidecar)        │   REST + WebSocket + OpenAPI
│  · 配置读写 data/config.db    │
│  · 审计/版本快照/回滚         │
│  · 密钥加密 (Windows DPAPI)   │
│  · Core 子进程管理 + env 注入 │
└──────────────┬───────────────┘
┌──────────────▼───────────────┐
│ 现有 Core (pelica/*)          │   人设/语料/管道/频控 原样复用
│  ↕ 桥接: wxhook | mock | …    │
└───────────────────────────────┘
```

发布形态（v1.1.0 起，已定）：**Tauri 安装包 + 自包含网关**（PyInstaller onedir 内嵌 FastAPI 网关与 pelica 核心，零 Python 依赖），发布版数据目录固定 `%APPDATA%\pelica-console`（开发模式仍用仓库 `data/`，双入口并存）。浏览器形态仅保留为开发调试入口（`控制台.bat`），不作为交付物。

| 层 | 选型 | 理由 |
|---|---|---|
| 桌面壳 | **Tauri 2**（备选：浏览器形态） | 安装包 ~10MB、内存占用低；Windows 用 WebView2 零额外依赖；updater 可对接现有 GitHub 发布流 |
| 前端 | React 19 + TypeScript strict + Vite | 生态最全；strict 与 zod 双端校验对齐 |
| UI | Tailwind v4 + **Radix 原语自建组件库** | Linear/Vercel 的质感来自自建设计系统；Radix 只提供无样式可访问性行为，避免"模板脸" |
| 服务端状态 | TanStack Query v5 | 配置类数据全是"远端资源"，缓存失效模型天然匹配 |
| 本地状态 | Zustand | 轻量，只放 UI 态 |
| 表格/表单 | TanStack Table + react-hook-form + zod | 白名单大表 + 复杂表单的标准答案 |
| API 契约 | 网关出 OpenAPI → orval 生成前端 client | 改后端字段前端编译期报错 |
| 数据 | SQLite（WAL）：`config.db`（新增）+ 现有语料 `data/*.db` | 与现有栈一致，零运维 |
| 密钥 | Windows DPAPI（`CryptProtectData`），macOS Keychain | 零第三方依赖，绑定当前用户 |
| 网关框架 | FastAPI + uvicorn，仅监听 127.0.0.1 | 异步 WS + OpenAPI 自带 |
| 数据访问 | 全部参数绑定查询（占位符），禁止拼接 SQL | 安全底线 |

## 2. 设计系统「Pelica DS」

取「Vercel 的中性 + Linear 的密度 + Raycast 的命令面板」三种气质，用佩丽卡/PRTS 的暖橙作品牌锚点（已定：采用佩丽卡橙）。

### 设计令牌（暗色为默认主题）

```
色彩
  bg-base      #0A0A0B   页面底
  bg-surface   #131315   卡片
  bg-elevated  #1B1B1F   弹层/悬停
  border       #FFFFFF0F 弱边框（层级靠边框+海拔色，不用重阴影）
  text-primary #F4F4F5   text-muted #A1A1AA（对比度 ≥7:1 / ≥4.6:1）
  accent       #FF7A1A   佩丽卡橙，hover #FF8C33，按下 #E56A0C
  success #3ECF8E · warning #F5A623 · danger #F0474A · info #4C8DFF
  状态一律「色点+文字」，不允许只用颜色区分（色盲可及）
字体
  UI: Inter + "MiSans / HarmonyOS Sans SC / 苹方 / 雅黑" 系统栈
  Mono（日志/ID/密钥）: "JetBrains Mono"
  字号 12/13(基准)/14/16/20/24，正文行高 1.6，正文行宽 ≤72ch
栅格与形状
  4pt 间距；圆角 6(控件)/10(卡片)/14(弹层)；图标统一 Lucide 24 viewBox
动效
  120ms 微交互 / 180ms 展开 / 240ms 页面转场，cubic-bezier(.25,1,.5,1)
  尊重 prefers-reduced-motion；悬停只变色变边框，绝不用 scale 挪布局
```

亮色主题同步交付（#FAFAFA 底、#0F172A 正文），跟随系统 + 手动切换。

### 五个自研关键组件

1. **TriState 开关**：继承（空心，显示继承来源）/ 开 / 关。继承态 hover 浮出"最终生效值：开（来自：全局）"。（P1 启用，P0 为两态）
2. **ScopeChip**：配置项右侧徽标 `全局` `群·xxx` `私聊` `用户`，点击打开**有效配置抽屉**（§4）。
3. **RiskBanner**：琥珀色横幅 + 橙左边条 + 一句风险 + 操作链接。不可关闭实例仅出现在首启向导与诊断页。
4. **CommandPalette（Ctrl+K）**：搜索一切（群、人设、开关、动作）。
5. **Do/Undo Toast**：所有写操作落盘前自动快照，Toast 带"撤销"（10 分钟内可回滚）。

可访问性基线：对比度 ≥4.5:1、焦点环可见、Tab 序 = 视觉序、图标按钮必须 aria-label、表单 label 绑定、动效尊重系统设置。

## 3. 信息架构与双模式

### 左侧导航（高级模式全量）

```
◉ 仪表盘          运行状态/消息量/健康度/告警
◇ 方案中心        一键切换整套行为
◇ 人设            角色包管理
◇ 语料库          知识库组合与检索测试
◇ 会话与白名单     群聊 · 私聊 · 黑名单
◇ 模型与 API      Provider/密钥/任务路由
◇ 功能开关        六大分组
◇ 测试沙箱        不碰微信的全链路试跑
◇ 日志与回放      实时日志 · 对话回放 · 审计
◇ 备份与诊断      快照/恢复 · 环境体检 · 更新
◇ 设置            外观/托盘/自启/数据目录
```

**简单模式**（默认）：只显示 `仪表盘 / 方案中心 / 会话与白名单 / 测试沙箱 / 日志`，方案中心以卡片呈现。模式只是视图过滤器，不是两套配置，切换不丢数据。

### 首启向导（8 分 30 秒路径）

```
① 欢迎+模式选择(15s) → ② 风险告知(30s，必须勾选) → ③ 连接微信(2min，可跳过)
→ ④ 选方案(1min) → ⑤ 填 Key+测试连接(90s) → ⑥ 沙箱试聊(2min)
→ ⑦ 选启用群(1min，默认保守频控) → ⑧ 完成页(15s)
```

- ③ 可跳过（先用沙箱玩）；mock 桥接模式下显示"示例群"代替真实群列表。
- ⑦ 允许"从最近会话导入"（wxhook 模式，P1）。
- 向导进度存 `config.db`，中断重开续走；第⑥步失败**不阻断**，给翻译后的错误 + "仍然完成"。
- 第②步风险文案（固定措辞，不许弱化）：

> 本程序的微信接入方式（WeChat-Hook）通过 DLL 注入修改微信客户端行为，不属于微信官方支持的接口。使用本程序存在账号被限制或封禁的风险。强烈建议：仅使用小号运行本程序；不要在承载重要账号的电脑上同时使用 hook。

## 4. 核心抽象：方案（Profile）与分层合并

系统的脊柱，七个模块都是它的投影。

**方案 = 五个引用的组合（引用 + 覆盖补丁，不复制内容）：**

```
Profile {
  persona_ref        → 人设版本（锁定版本号）
  corpora_bindings   → [ {corpus_ref, weight, priority} ]
  model_route        → {qa, chat, classify, weekly} → 各自 provider+model
  flags_overlay      → 功能开关的 JSON Merge Patch
  reply_policy       → 触发方式/冷却/每日上限/静默时段/回复长度
}
```

**作用域栈与合并算法**（RFC 7396 JSON Merge Patch，一句话可解释："下面的覆盖上面的"）：

```
方案默认  ⊂ 全局  ⊂ 群聊/私聊(可选)  ⊇ 用户(可选)   →  有效配置
```

- 任何字段的 ScopeChip + "有效配置抽屉"逐层摊开合并结果：`冷却 30s（群覆盖）← 继承自全局 60s ← 方案默认 60s`。
- 该抽屉同时是**排障入口**："机器人为什么没回话？"沿栈逐层检查触发条件、白名单、频控、静默、Key 余额，给出第一个命中的拦截原因。

### 数据模型（`data/config.db`）

```
profiles          id, name, icon, is_builtin, base_profile_id, version, created_at
profile_versions  profile_id, version, manifest(JSON, 不可变快照), created_at, note
personas          id, name, toml_source, persona_md, enabled, scope_default
persona_versions  persona_id, version, content, created_at
corpora           id, name, release_dir, db_path, doc_count, entity_count,
                  index_status(pending|building|ready|failed), size, updated_at
corpus_bindings   owner(scope), corpus_id, weight(0-1), priority(1-9)
sessions_groups   wxid, name, remark, tags, trigger_mode, member_policy,
                  status(active|paused), quiet_hours, overrides(JSON),
                  last_active_at, expires_at(临时白名单)
sessions_private  wxid, nickname, remark, role(admin 不可删), mode,
                  blacklisted, expires_at, last_active_at
providers         id, kind(deepseek|openai|zhipu|kimi|openrouter|custom),
                  base_url, encrypted_key, key_hint("sk-****f3a2")
model_routes      scope, task(qa|chat|classify|weekly), provider_id, model, params(JSON)
flags             scope, flag_key, value(true|false|inherit)
audit_log         id, ts, actor(ui|wizard|import), action, target,
                  before(JSON), after(JSON), undo_token
snapshots         id, ts, kind(auto|manual|pre-change), payload_path, size, note
settings          key, value(JSON)
```

所有写操作先写 `audit_log`（before/after 全量快照）——**版本回滚、差异对比、撤销全部由这一张表驱动**，不为各模块单独造历史机制。

## 5. 模块设计

### 5.1 方案中心

- 首屏三张内置方案大卡：`佩丽卡 × PRTS × DeepSeek`（默认）、`凯尔希 × PRTS`、`派蒙 × 原神语料`（三个角色包已就绪）。卡片显示：人设名、语料徽标、模型徽标、一句话简介、"已应用"状态。
- **自定义方案**：从任一卡片"复制"进入四步编辑（人设 → 语料组合 → 模型 → 开关），每步是引用选择器而非编辑器。
- **应用**：P0 = 应用为全局默认角色（等价 `CHARACTER=<id>`，经网关注入）；P1 = 应用到指定群（写 `sessions_groups.overrides`）。切换方案前自动建快照，卡片菜单"回到切换前"一键回滚。
- **导入导出**：`.pelica-profile.json` 单文件（manifest + 人设全文 + 语料清单，**不含密钥**）。导入时语料不存在则明确提示，不静默降级。

### 5.2 人设管理

对接 `characters/*.toml + .persona.md` 双文件结构，保存时网关同时写两个文件（git 里的角色包格式不变，CLI 用户无感）。

```
┌─ 编辑器 ────────────────────────────┬─ 实时预览 ─────────────┐
│ 昵称 [佩丽卡]  签名 [基于PRTS的…]    │  ▸ 最终系统提示词       │
│ ▸ 基础（口吻/回复长度/禁词/机器腔）   │    （变量已插值，等宽）  │
│ ▸ 系统提示词（Markdown 编辑器）       │  ▸ 变量检查             │
│ ▸ 示例对话（成对添加）               │    {group} {user} ✓    │
│ ▸ 进阶（@别名/出处话术/变量）        │    {近况} ⚠ 未定义      │
│ ────────────────                   │  ▸ 模拟一条群消息预览   │
│ 保存并测试   版本历史(12)   作用域    │    （调沙箱，2s 出结果）│
└────────────────────────────────────┴────────────────────────┘
```

- 禁词 = 标签输入，命中时预览高亮；机器腔过滤三档（关/标准/严格，标准档预置"作为一个AI/很抱歉"等短语库）。
- 版本历史：列表 + 恢复（P0）；双栏 diff（P1）。
- 导入角色卡：SillyTavern PNG/JSON 解析为结构化字段，落"待整理"分区并引导补齐（P1）。
- 作用域：群可在群详情"覆盖人设"，此处显示反向引用（P1）。

### 5.3 语料库管理

- 卡片墙：`doc/entity 数`、大小、更新时间、索引状态灯（灰排队 / 蓝构建中带进度 / 绿就绪 / 红失败+重试）。数据来自 `corpus/releases` 扫描 + `data/*.db` 统计。
- 多库组合（P1）：拖拽排序的权重列表——顺序即优先级 + 权重滑杆；保存触发旧检索缓存清理（防串库），Toast 明示。
- **检索测试台**（灵魂功能，P0 基础版）：

```
问题 [阿米娅的档案里说了什么？]           上下文 ▾ (当前角色语料)
─────────────────────────────────────────────
证据 Top-5   ① 主库 0.87  《理智/阿米娅》        [展开原文]
             ② 主库 0.71  《干员档案》片段        [展开原文]
最终回复     （流式渲染，带 [1][2] 引用角标）
耗时/Token   检索 340ms · LLM 1.2s · 共 812 tok ≈ ¥0.001
```

- 索引操作：重建走后台子进程（复用 `scripts/build_db.py` 语义），进度经 WS 推卡片；失败保留错误全文 + 重试。构建期间旧索引继续服务。
- 来源引用：开关 + 格式（角标/尾注/隐藏）。

### 5.4 会话与白名单

**群聊页**：工具栏（搜索 / 状态过滤 / 批量操作 / CSV·JSON 导入导出）+ 表格（群名、备注、触发方式、状态点、最后活跃、临时标识）。行点击进**群详情**：

```
群详情：PRTS闲聊群 (wxid_xxx…)      [启用 ⬤]  [⋯ 导出/删除/静默时段]
┌ 基本-card ──┬ 覆盖-card ──────────────┬ 成员-card ─┐
│ 备注/标签    │ 人设[继承▾] 语料[继承▾]  │ 成员白名单  │
│ 触发方式 ◉@ │ 触发[继承▾] 频控[继承▾]  │ ◉全部成员  │
│ ○关键词○回复│ 每项三态+ScopeChip       │ ○仅管理员   │
│ ○全部消息   │ 底部：查看有效配置(抽屉)  │ ○指定成员…  │
└────────────┴────────────────────────┴───────────┘
```

- 覆盖卡片一旦改动出现"已覆盖 N 项 · 全部还原"提示条——**让"改了什么"永远可见**。
- 临时白名单：24h / 7 天 / 永久，倒计时沙漏图标，到期由网关定时任务移除 + 系统通知。
- 成员白名单、从最近会话导入（wxhook 群列表）为 P1。

**私聊页**：同构表格（昵称、wxid、备注、角色、模式、状态、到期）。私聊模式四选：仅指令 / 仅关键词 / 正常闲聊 / 全部允许。**管理员行置顶、锁形图标、删除禁用** + tooltip"管理员默认放行且不可移除"。黑名单独立 tab，拉黑二选一："拉黑并静默（不记录）/ 拉黑但保留记录"。

### 5.5 模型与 API

- **Provider 预设卡**：DeepSeek / OpenAI / 智谱 / Kimi / OpenRouter / 自定义。选卡 → 贴 Key → **测试连接**（真实最小补全，成功显示延迟 + 模型列表 + 余额，三绿灯才算过）。
- **密钥安全三件套**：DPAPI 加密落库；界面永远 `sk-****f3a2`（点复制完整值需二次确认）；网关日志中间件对 Key 做正则脱敏后才落盘/推送。
- **任务路由表**（P1，P0 只有默认模型一行）：问答/闲聊/分类/周报各配 provider+model（分类用便宜档、周报用重推理档）。
- **错误翻译表**（内置维护）：

| 原始错误 | 翻译 | 动作按钮 |
|---|---|---|
| 401 | 密钥无效或已过期 | [去修改] |
| 429 / rate limit | 调用太频繁或额度受限 | [查看频控] |
| insufficient_balance | 余额不足 | [充值链接] |
| ECONNREFUSED 127.0.0.1:30001 | 微信桥接未启动 | [启动桥接] |
| timeout | 模型服务响应超时 | [重试] |

  每个错误右侧都带动作按钮——**翻译不是文案，是入口**。
- P1 用量页：按任务/群/天的 Token 与费用曲线 + 预算线 + 超额动作（只提醒/降级模型/暂停回复）。

### 5.6 功能开关

六分组：对话能力 / 内容解析（抖音、B站）/ 定时互动（周报、问好）/ 消息与频控 / 安全过滤 / 高级实验（默认折叠 + "可能不稳定"徽标）。

- **简单模式**：三个套餐卡——极简（仅@触发+周报关）/ 标准（@+关键词+链接解析，推荐）/ 全能（全部+回复触发）。选套餐 = 应用一组 flags_overlay，卡片下方一句话列出与当前的差异。
- **高级模式**：开关墙，每行 = 名称 + 开关 + 说明折叠 + `推荐` 角标 + 依赖提示。P0 为全局两态；P1 升三态 + 作用域链。
- 依赖校验示例：开"抖音解析"但下载目录不可写 → 行内黄条 + [修复]；开"周报"但时区未设 → [跳去设置]。冲突提示让用户二选一，**永不静默取默认值**。
- 影响预览（P1）：底部浮出常驻条"N 个群受影响 · 查看"。

### 5.7 日志、沙箱、备份、诊断

**日志页**：三 tab（实时 / 对话回放 / 审计）。实时流走 WS + 级别筛选 + 搜索 + 暂停滚动；错误行内联翻译条。对话回放（P1）：按群/时间选会话，气泡流 + 每条气泡展开**管道视图**（触发判定 → 白名单 → 检索证据 → 提示词 → LLM 原始输出 → 后处理）。审计 = `audit_log` 时间线，可展开 before/after 并"撤销"（可撤销期内）。

**测试沙箱**（mock 桥 UI 化）：左侧模拟器（身份：群成员/私聊对方；输入：文本/@/链接），右侧结果面板（回复气泡 + 管道视图 + 提示词全文 + 证据 + 耗时 + Token + 费用估算）。顶部上下文选择器：用哪个群的有效配置跑——**沙箱跑的就是真实配置**。

**备份与诊断**：备份 = 配置 DB + 人设 + 白名单（不含语料索引，恢复后提示重建）打包 zip；本地（P0）/ WebDAV / S3（P1）；手动 + 自动（每日/每次大改前）。诊断 = 环境体检清单：Python 版本 / 微信版本是否 4.1.10.27（不符则橙警 + 指引）/ hook 端口连通 / Key 余额 / 磁盘空间 / 桥接心跳；每项 [一键修复] 或明确指引；断连出系统通知 + 自动重连倒计时。

**系统集成**：托盘常驻（运行中/静默/离线三态）、最小化到托盘、开机自启（默认关，首启完成页询问一次）、快捷键（Ctrl+K / Ctrl+Shift+S 快速沙箱）、自动更新 + 保留上一版可回滚（P2）。

## 6. 安全设计（不可妥协项）

- **首启向导第②步整屏风险告知**（§3 固定文案），不勾选不能继续。
- 仪表盘常驻可折叠 RiskBanner："当前使用注入式桥接，建议使用小号运营。[查看安全建议]"；安全建议页含频控保守化清单（全局冷却 ≥30s、每日上限、静默时段示例）。
- 微信版本不匹配 = 诊断页最高优先级告警。
- 密钥：DPAPI 加密、界面掩码、日志脱敏三件套；导出任何数据前扫描并剥离密钥字段，导出对话框明示"已自动去除 N 个密钥"。
- 全部数据本地：网关只监听 127.0.0.1 随机端口 + 启动握手 token；除用户显式配置的 LLM API 与备份目标外零外联（诊断页可见"外联清单"）。
- SQL 全参数绑定；源码/示例/测试不出现可用凭据字面量。
